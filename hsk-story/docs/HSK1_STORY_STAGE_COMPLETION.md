## Current state and invariant

The live task IDs are array positions `0–9` in `content-manifest.js` / `curriculum-data.js`, persisted as `chimse-branch-learning-v1` and represented in objective evidence by `chimse.hsk1-demo.scene.<index>`. Current introduction/practice is in tasks `0–6`. Tasks `8` (price) and `9` (ordering) are separate responses, but currently fire at `day2-bird`, before the later second-visit scene `day2-liu`. Put common-route learning beats on those shared nodes or after their convergence, never behind one selected option.

## Wording and evidence rules

- Context-use lines are story writing and award no learning evidence. They must be understandable from the scene and must not display the answer to an immediately following independent prompt.
- Independent prompts are learner-facing Vietnamese; Chinese, Pinyin, translations, and samples remain hidden until an attempt or explicit help request according to the current checkpoint policy.
- A measured response maps to exactly one `assessmentObjectiveId`. Task 7 remains its historical single response with its historical two-objective association; do not backfill separate per-objective evidence from it. Tasks 10–17 are the first separate evidence for these delayed recall opportunities.
- Wrong, assisted, sample-viewed, and skipped statuses remain learning evidence only; they do not alter story route, memory, relationship, or ending. Preserve current answer rubrics and add accepted alternatives only after language review.
- Phrase examples above are drawn from the current authored materials; all objective mappings, Pinyin, pronunciation, and accepted alternatives still require the planned educator/native-speaker review.

## Save, migration, and implementation implications

1. Keep task indexes and task IDs `0–9`, curriculum crosswalks, storage key, and old accepted evidence byte-compatible. Append new curriculum rows `10–17`; do not insert or sort rows into the old range.
2. `branch-learning.clean()` currently pads a history to `content.scenes.length`. After appending content, verify old ten-slot histories load with eight `null` entries and continue at the next reached new anchor. Do not synthesize completion for appended tasks.
3. `objectiveEvidence()` and `fromObjectiveEvidence()` use task IDs plus the curriculum assessment crosswalk. Each appended row must name one objective only; ensure old task 7 still round-trips exactly as stored and no migration claims it answered two independent prompts.
4. Branch path state and learning history remain separate. Rewind must preserve all objective evidence; revisiting an already completed new prompt must not duplicate or erase it. Route changes must still reach the same new mandatory anchors.
5. Keep HSK1 status as pilot/incomplete pending source matching and educator review; eight objectives here do not establish official coverage, proficiency, or exam readiness.

## Required verification before enabling

- Verify every day-two branch crosses the new anchors in chronological order: context use first, then the matching one-objective recall. No single branch-only choice may be prerequisite to the cue or recall.
- Confirm a response at each of tasks `10–17` creates evidence for only its one objective. Confirm task 7 old saves still round-trip without rewriting its historic shape.
- Load a pre-change ten-slot save, reach new anchors, rewind before/after them, reload, and confirm appended tasks start unanswered while old results remain unchanged.
- Compare complete-route exposure across branches and keep the existing answers/early task results intact. Try wrong, helped, sample, skipped, and correct responses; none may change story memory or route.
- Measure the actual session time on desktop and phone. The 10–15 minute target is not met merely because the task count is small.
- Obtain educator review for the source crosswalk and Chinese/Pinyin before any of these tasks are marked approved or included in a public claim of HSK1 completeness.
