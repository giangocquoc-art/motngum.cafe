# Authored content contract
- HSK reference: HSK 3.0 syllabus edition 2025-11 (effective 2026-07), not the legacy six-level syllabus. The official notice schedules worldwide launch for 2026-12-13. `HSK3_SOURCE_AUDIT.md` records the source, rollout date, and printed page anchors. Only HSK1 has an existing playable pilot. Levels 2–6 remain locked until review gates pass.
- The six-level registry uses stable objective IDs and keeps the five HSK 3.0 components separate. `hsk30-syllabus-inventory.json` contains source IDs, printed pages, source hashes and official counts for all level 1–6 tasks, topic tiers, vocabulary rows, recognition characters and grammar pages. It does not copy the PDF tables; merged topic hierarchy and grammar item normalization still need review. HSK1 has eight candidate goals linked to the ten existing lesson/checkpoint records. HSK2–6 each have six curated story-spine candidates with selected word serial/page, target-level grammar/page, character recognition-list level/ordinal/page, skill references, stages, prerequisites and review states. `candidate-source-index.json` validates those selected items. The instructional objective crosswalk and educator sign-off remain incomplete; the full source locator inventory must not be presented as complete syllabus coverage.
- Before a level can be released, every objective needs an in-context introduction, later reuse, an independent checkpoint, a reviewed clue policy, and an educator-approved item crosswalk. The HSK1 pilot now has authored opportunities for all three learning stages; some are in optional spaced review rather than required story scenes. The blueprint still blocks release until item-level HSK mapping and educator review are complete. Future objective outlines name a separate recall beat after later story use, even when that beat will live in the capstone episode.
- Every scene must have an immutable numeric or namespaced ID, chapter ID, place, time, character speaker, natural-language objective, HSK level, teaching/practice or checkpoint kind, prerequisite links, target words and grammar, Chinese dialogue, Pinyin and optional Vietnamese, accepted response intent, curated variants, hint policy and next scene.
- First introduce an objective, then repeat it through normal in-world dialogue, and only later assess independent recall. Checkpoints contain no brand-new mandatory content.
- Canonical story state/choice memory is separate from objective-keyed learning evidence. Each narrative choice has a distinct authored response, a durable memory and a later visible consequence, then rejoins before the next mandatory objective. Every branch presents equivalent learning objectives and practice opportunities.
- `future-branch-decisions.json` contains two authored route treatments for each future episode. They are still non-playable; each option carries a branch scene, distinct response, memory value, later consequence, shared rejoin, and common candidate objective anchors. Runtime unlock waits for reviewed HSK mapping, lesson/assessment authoring, art, and educator approval.
- `objectiveIds` describe goals present in a scene; `assessmentObjectiveIds` list only what the accepted answer actually evaluates. Optional review cards keep stable IDs and are tagged by objective and stage; they do not rewrite the ten canonical lesson records or story save keys.
- A wrong answer, hint, sample or skip changes only learning evidence and in-scene feedback; it never changes route, relationships, personality or ending. Wrong answers can be retried. Skipped work is recorded as non-mastery. NPC responses must preserve character facts, location and stakes and never reveal checkpoint answers.
- Answers must be evaluated for meaning/intent in a validated AI grading phase; prototype uses conservative explicit templates, with known false negatives possible.
- Help is visible and consentful: showing a hint, pinyin/translation during a checkpoint or revealing a sample must reduce or change independent credit.
- Episode completion is NOT HSK certificate readiness. Repeated attempts can be used for formative practice; future exam rubrics need distinct skill-level evidence.
- Professional review required before a level is advertised or released: qualified Mandarin/HSK educator, item-level syllabus mapping, idiomatic Chinese/Pinyin/translation, and appropriate skill evidence. Story activities do not imply exam readiness or certification.
- Content implementation: `learning-blueprint.js` is a source-pinned HSK 3.0 level 1–6 objective registry; `hsk30-syllabus-inventory.json` provides the complete source locator corpus, `candidate-source-index.json` carries independent locators for selected candidate items, and `curriculum-data.js` holds the current HSK1 pilot metadata. The review schema can represent pending, matched, reviewed-with-no-match, educator-approved, and release-ready states, but current official item matches and educator sign-offs remain zero/pending. The instructional crosswalk is not complete.
