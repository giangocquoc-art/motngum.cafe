# Authored content contract
- HSK reference: HSK 3.0 syllabus edition 2025-11 (effective 2026-07), not the legacy six-level syllabus. The official notice schedules worldwide launch for 2026-12-13. `HSK3_SOURCE_AUDIT.md` records the source, rollout date, and printed page anchors. Only HSK1 has an existing playable pilot. Levels 2–6 remain locked until review gates pass.
- The six-level registry uses stable objective IDs and keeps the five HSK 3.0 components separate. `hsk30-syllabus-inventory.json` contains source IDs, pages, hashes and official counts for all level 1–6 tasks, 512 geometry-derived topic cells, 5,400 vocabulary rows, 1,940 recognition characters, 17 grammar pages and 459 extracted grammar source rows. The grammar source-row count is an extraction diagnostic, not an official item total. Page-level geometry was visually reviewed; full cell-text verification and educator alignment remain pending. HSK1 has eight candidate goals linked to the ten existing lesson/checkpoint records. HSK2–6 each have six curated story-spine candidates with selected word serial/page, target-level grammar/page, character recognition-list level/ordinal/page, skill references, stages, soft prior-exposure prerequisite status and review states. Future prerequisites are not inferred from goal order and do not unlock content. `candidate-source-index.json` validates those selected items. The instructional objective crosswalk and educator sign-off remain incomplete; the full source locator inventory must not be presented as complete syllabus coverage.
- Before a level can be released, every objective needs an in-context introduction, later reuse, an independent checkpoint, a reviewed clue policy, and an educator-approved item crosswalk. The HSK1 pilot now has authored opportunities for all three learning stages; some are in optional spaced review rather than required story scenes. The blueprint still blocks release until item-level HSK mapping and educator review are complete. Future objective outlines name a separate recall beat after later story use, even when that beat will live in the capstone episode.
- Every scene must have an immutable numeric or namespaced ID, chapter ID, place, time, character speaker, natural-language objective, HSK level, teaching/practice or checkpoint kind, prerequisite links, target words and grammar, Chinese dialogue, Pinyin and optional Vietnamese, accepted response intent, curated variants, hint policy and next scene.
- First introduce an objective, then repeat it through normal in-world dialogue, and only later assess independent recall. Checkpoints contain no brand-new mandatory content.
- Canonical story state/choice memory is separate from objective-keyed learning evidence. Each narrative choice has a distinct authored response and later callback, then rejoins before common learning anchors. Future objective order follows each act's episode order. Any later-added prerequisite means prior exposure only and must be introduced before the dependent objective; it never gates progression or grants mastery.
- `future-branch-decisions.json` contains two authored route treatments for each future episode. `future-branch-runtime.js` compiles a separate internal author-preview graph for every HSK2–6 act (`forLevel(level)`); the default HSK2 API and version-one IDs remain compatible. Routes follow actual next/choice/conditional-skip edges. Each act's 16 complete routes, every reached partial save, and rewinds at every decision are checked for shared, ordered introduction/reuse/checkpoint anchors and selected-only consequences. Cycles, anchor shortcuts and corrupt evidence are rejected. These graphs contain planning anchors, not authored lessons or assessments. They are not loaded by the game; HSK2–6 remain non-playable and HSK1 saves are unchanged. Plot saves contain the versioned act ID, chronological choices, and validated node-ID path; memory text and callback content are rebuilt from authored choices. Learning evidence is stored separately and only at its matching checkpoint. Runtime unlock waits for reviewed HSK mapping, complete lessons/assessments, art, and educator approval.
- `objectiveIds` describe goals present in a scene; `assessmentObjectiveIds` list only what the accepted answer actually evaluates. Optional review cards keep stable IDs and are tagged by objective and stage; they do not rewrite the ten canonical lesson records or story save keys.
- A wrong answer, hint, sample or skip changes only learning evidence and in-scene feedback; it never changes route, relationships, personality or ending. Wrong answers can be retried. Skipped work is recorded as non-mastery. NPC responses must preserve character facts, location and stakes and never reveal checkpoint answers.
- A guided model's `speaker` and `speakerCharacter` override the scene's default speaker. Both players use the shared renderer's `setSpeaker(host, character)` for spoken turns. It temporarily pauses other speaking actors while preserving their emotional frames; `restoreSpeaker` and the next `mount` release only owned changes. Character expressions changed independently remain intact.
- Answers are checked against each task's declared communicative intent. The current pilot uses deterministic accepted templates, with known false negatives possible. Accepted variants and learning-evidence rules remain versioned; a new grading provider would require separate rubric validation.
- Help is visible and consentful: showing a hint, pinyin/translation during a checkpoint or revealing a sample must reduce or change independent credit.
- Episode completion is NOT HSK certificate readiness. Repeated attempts can be used for formative practice; future exam rubrics need distinct skill-level evidence.
- Professional review required before a level is advertised or released: qualified Mandarin/HSK educator, item-level syllabus mapping, idiomatic Chinese/Pinyin/translation, and appropriate skill evidence. Story activities do not imply exam readiness or certification.
- Content implementation: `learning-blueprint.js` is a source-pinned HSK 3.0 level 1–6 objective registry; `hsk30-syllabus-inventory.json` provides the complete source locator corpus, `candidate-source-index.json` carries independent locators for selected candidate items, and `curriculum-data.js` holds the current HSK1 pilot metadata. The review schema can represent pending, matched, reviewed-with-no-match, educator-approved, and release-ready states, but current official item matches and educator sign-offs remain zero/pending. The instructional crosswalk is not complete.
